# Deposit MUSIC-01 — MusicGen program for ODIN's demo video

## What the program does

[musicgen_modal.py](musicgen_modal.py) runs Meta's MusicGen on a single
Modal GPU (A10G, 30-minute timeout) to make an instrumental bed for
ODIN's demo video:

1. Takes — several 30 s theme takes from prompts/theme.txt, each with
   its own seed, each saved as a 32 kHz stereo WAV with a JSON sidecar
   (model, prompt, seed, duration, AudioCraft version, GPU, SHA-256).
2. Extend — continues a picked take to full length in overlapping
   windows, re-feeding the last 10 s, never restarting the music.
3. Compose — builds the 180 s piece at 108 BPM from a picked theme
   take: the take opens unchanged, the development continues it with
   prompts/develop.txt, and a reprise generated by the melody model
   from prompts/reprise.txt is joined with a one-bar equal-power
   crossfade on a bar line, with a two-bar fade-out. Generation is
   length-safe: every window and the reprise is asked for a little
   more than planned, rounded up to whole 50 fps codec frames, trimmed
   to the plan, and any shortfall is generated rather than failing, so
   the result is exactly the planned total. The development and the
   reprise are saved as their own WAVs, each with its JSON, before
   anything is joined, and a local `join` command re-joins saved
   sections with no GPU, no Modal and no torch.

Only the JSON sidecars of the audio are in this deposit. No WAVs are
included. A cut of the composed track, made by the Director, goes in
the video.

## Tests

Run on the Director's machine from the project folder, with the local
`.venv` (Python 3.14.4, no torch installed):

    .\.venv\Scripts\python.exe -m unittest discover -s tests -v

Result on 1 November 2026: 61 tests ran, all passed (`OK`).

Every behaviour has a planted red case beside it — bad input that
must be rejected, or tampered data that must be detected. Each was
shown failing against the real code, for example:

- empty prompt and missing prompt file are rejected;
- duplicate seeds, zero takes and an unlisted model are rejected;
- a tampered WAV fails its sidecar SHA-256 check, and a sidecar
  missing a field (for example `gpu`) is rejected;
- a 22 050 Hz WAV is rejected (32 kHz stereo is the contract);
- extend with target equal to current length, and overlap equal to
  the window, are rejected;
- the incompatible torch 2.3.1 pin is not in the cloud image packages;
- a partial stereo frame is rejected, and out-of-range samples clamp
  instead of wrapping;
- non-positive BPM and a total not exceeding theme plus reprise are
  rejected;
- a linear crossfade is the planted wrong method: its mid-fade RMS
  falls to about 0.733, failing the equal-power level check that the
  real crossfade passes;
- mismatched crossfade lengths and an empty crossfade are rejected;
- a compose section missing `prompt_file` is rejected;
- a negative codec length and a sample rate not divisible by the
  50 fps codec frame rate are rejected;
- a crossfade past the total, a channel mismatch, and ragged channels
  are rejected;
- a fade start at or beyond the track end, and a negative fade start,
  are rejected;
- an 8-bit WAV is rejected by the 16-bit PCM decoder, and a saved
  section at the wrong sample rate is rejected by the join.

The length safety added after the first compose attempt is covered
directly: sections a few samples short, a few samples long, and exact
all assemble to exactly the planned total with the crossfade on its
bar line, through both the in-memory assembly and the GPU-free join
of saved WAV bytes, and generation requests round up to whole codec
frames. The original failure — a development 427 samples short of
the plan, so the crossfade bar was not all there — is the short case
in those tests.

## Models and licences

- facebook/musicgen-stereo-large — theme takes and development.
- facebook/musicgen-stereo-melody-large — the reprise.
- AudioCraft 1.3.0 in Modal's cloud image (torch 2.1.0).

MusicGen's code is MIT-licensed and its model weights are licensed
CC BY-NC 4.0. Neither the MusicGen code nor any model weights are
stored in this deposit; the weights were downloaded only inside
Modal's container. They are used here for a noncommercial,
open-source demo.

## Secret and path scan

Before zipping, every file in this deposit was scanned for API keys,
tokens and their values, private keys, user names, e-mail addresses
and machine paths. Nothing of that kind was found. The only matches
were the variable names MODAL_TOKEN_ID and MODAL_TOKEN_SECRET, with
no values, in musicgen_modal.py and README.md: Modal reads those from
the user's environment, and no credential is stored in any file here.
The 64-character hex strings in the sidecars are the SHA-256 hashes
of the WAV files, as labelled. The Modal app identifier above was
supplied by the Director for this record.
